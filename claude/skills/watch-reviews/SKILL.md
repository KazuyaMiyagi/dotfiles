# レビュー依頼と PR の見張り

`gh-watch-review-requests` と `gh-watch-pr-activity`（dotfiles の `bin/`）を
バックグラウンドで動かし、通知を受けたら次の手順まで進める。
どちらのスクリプトも 1 件拾ったら終わるので、拾うたびに仕掛け直す。

## 1. 見張る対象を決める

- 自分宛てのレビュー依頼は、いつも見張る
- 引数に PR（URL か `owner/repo#番号`）が渡されたら、その PR の動き（書き込み・push・CI の結果・マージ）も見張る。
  自分の PR で人の承認を待っているもの、こちらのコメントへの返事を待っているものなど
- 引数が無ければ、前のセッションから引き継いだ PR が無いかをユーザーに聞く。
  無ければ、レビュー依頼だけを見張る

## 2. 見張りを仕掛ける

どちらも `run_in_background` で動かす。

```bash
gh-watch-review-requests [SINCE]
gh-watch-pr-activity <owner>/<repo> <PR>
```

- `gh-watch-review-requests` の `SINCE` は、初回は省いて今から見張る。
  仕掛け直すときは、前回の出力の `next_since` を渡す
- 同じ PR に `gh-watch-pr-activity` を二重に仕掛けない。
  仕掛けている見張りは、タスクの一覧で確かめる

## 3. 通知を受けたら

### レビュー依頼が来たとき

1. 出力に並んだ PR を、peer-pr-review の手順でピアにレビューを頼む
2. `next_since` を渡して `gh-watch-review-requests` を仕掛け直す
3. ピアの結果が届いたら、peer-pr-review の手順で 1 件ずつ承認するかを聞く

### PR に動きがあったとき

出力の行の頭で、何が起きたかが分かる。

- `comment`・`review`・`thread`：書き込みが増えた
- `commit`：ほかの人がコミットを push した
- `checks`：head のコミットの CI が終わった（`SUCCESS`・`FAILURE`・`ERROR`）
- `state`：PR がマージ・クローズされた（`MERGED`・`CLOSED`）

1. 増えた書き込みを全文で読み、要点をユーザーに伝える。
   コミットが増えたときは、その差分を確かめて伝える。
   CI が落ちたときは、落ちたジョブと原因を確かめて伝える
2. 次の手順を決める
   - 指摘や質問なら、返信や修正の案を作り、文面と差分をユーザーに見せて確認を取る
   - 修正の push なら、こちらの指摘や依頼どおりに直っているかを確かめ、承認するかをユーザーに聞く
   - 承認なら、人の承認が揃ったかを確かめる。
     揃っていれば、リポジトリの指示ファイルにあるマージの手順（pr-merger の枠など）に進む
3. まだ待つ必要があれば、同じ PR に `gh-watch-pr-activity` を仕掛け直す。
   マージ・クローズされた PR に仕掛けると、エラーで終わる

## 4. 止める

- PR がマージ・クローズされたら（`state` の行が出たら）、その PR の見張りは仕掛け直さない
- ユーザーに止めるよう言われたら、仕掛けている見張りをすべて止める
- 12 時間なにも来ずにスクリプトがエラーで終わったら、そのことを伝え、続けるかを聞く
